# i18n 国际化规范

## 翻译文件规范

1. **语言一致性**：i18n 目录下所有的翻译文案必须与对应目录语言保持一致
   - 例如：`i18n/zh/` 目录下的文件内容必须是中文
   - `i18n/en/` 目录下的文件内容必须是英文

2. **翻译完整性**：翻译文件中除了下划线开头的私有键以外，所有键值都应该被翻译
   - ✅ 正确示例：
     {
       "_meta": "这是私有键，不允许翻译",
       "welcome": "欢迎",
       "login": "登录"
     }
   - ❌ 错误示例：
     {
       "welcome": "welcome",  // 未翻译
       "login": "登录"
     }

3. **私有键约定**：以下划线 `_` 开头的键被视为私有键
   - 私有键不允许翻译，通常用于元数据、配置信息等
   - 例如：`_version`, `_author`, `_description`

4. **占位内容**：一些自动生成的 key 可能包含占位内容
   - 占位内容一般为 key 所在的路径，如：{ "Auth: { "key": "Auth.key" } }
   - 所有占位内容都应该按照其对应意思进行翻译

## 检查清单

- [ ] 所有非私有键都已按照目标语言翻译
- [ ] 翻译内容符合目标语言的表达习惯
- [ ] 私有键（以 `_` 开头）可以保持原样
- [ ] 同一概念在不同文件中翻译保持一致
